# Сервер 33 · Z Route: Redemption

Неофициальный сайт сообщества 33 сервера. Показывает, у кого из альянсов
получается побеждать в VS, а у кого нет — на конкретных итогах недели.

**Правило рейтинга простое:** победа `+1`, поражение `−1`. Третьего не дано —
в VS альянс участвует всегда, и исход бинарный. Пустая ячейка в таблице означает
не «пропустил», а «результат ещё не внесли».

Со временем из этого складывается картина, которую в игре нигде не увидеть.

## Разделы

| Раздел | Что показывает |
|---|---|
| Итоги недели | Кто победил, кто проиграл, кто поднялся и упал. Главный экран |
| Рейтинг | Все 32 альянса: очки, форма, серии, график динамики |
| Хронология | Когда какой сервер был захвачен |
| Малым алам | Образцовое руководство альянсом и выгоды крупного альянса |

## Запуск

Зависимостей нет, сборки нет. Нужен только Node для скриптов и тестов.

```bash
node scripts/gen-demo.mjs            # сгенерировать демо-данные
node tests/contract.test.js          # прогнать тесты
node scripts/build-preview.mjs       # собрать dist/preview.html одним файлом
node scripts/build-admin-preview.mjs # собрать превью админ-панели на выдуманных данных
node scripts/make-sheet-template.mjs # собрать шаблон Google Таблицы
node scripts/check-sheet.mjs <ID>    # проверить живую таблицу
node scripts/pull-sheet.mjs          # выгрузить таблицу в data/live.json
```

Сам сайт — статика. Локально удобно так:

```bash
python3 -m http.server 8000   # затем открыть http://localhost:8000
```

Просто открыть `index.html` двойным кликом не получится: браузер запрещает
ES-модули с `file://`. Нужен любой локальный сервер.

## Архитектура: переключение источника данных

Источник данных меняется **одной строкой** в [`config.js`](./config.js):

```js
dataSource: 'sheets',   // 'json' | 'sheets' | 'pocketbase'
```

- **`json`** — файл рядом с сайтом. **Рабочий режим.**
- **`sheets`** — Google Таблица напрямую из браузера. Полезен для проверки.
- **`pocketbase`** — своя база с админкой. Включается, когда появится человек,
  отвечающий за сервер.

### Почему рабочий режим — json, а не sheets

Сначала сайт читал таблицу прямо из браузера, и это было красиво: правка
в таблице появлялась на сайте через пару минут сама.

Но для российской аудитории так нельзя. Google в РФ работает нестабильно,
и часть игроков увидела бы пустую страницу — причём хостинг тут ни при чём,
проблема в самой цепочке.

Поэтому таблицу читает **не браузер, а GitHub Actions** по расписанию раз
в полчаса: [`scripts/pull-sheet.mjs`](./scripts/pull-sheet.mjs) забирает данные
и коммитит [`data/live.json`](./data/live.json). Посетитель обращается только
к нашему домену.

Для доверенного человека ничего не изменилось: он правит ту же таблицу.
Разница только в задержке — полчаса вместо мгновенно. Не хочется ждать —
на вкладке **Actions** есть кнопка ручного запуска.

Побочная выгода: сайт стал полностью самодостаточной статикой. Переехать
на другой хостинг теперь можно за пять минут, если выбранный однажды
заблокируют.

**Две защиты в скрипте выгрузки:**

1. Если таблица не проходит валидацию — выгрузка отменяется, старые данные
   остаются. Сломанная таблица не может обрушить работающий сайт.
2. Если данных внезапно стало вдвое меньше — тоже отмена. Частичный ответ
   Google формально корректен, но записать его означает обнулить сайт.

В обоих случаях workflow падает, и GitHub присылает письмо.

**Про расписание есть одна ловушка:** GitHub отключает workflow по расписанию
после 60 дней без активности в репозитории. Перед отключением приходит
письмо — достаточно нажать кнопку, чтобы включить обратно.

Подробности и обоснование — в [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md).

## Админ-панель без сервера

[`admin.html`](./admin.html) — своя панель управления. Отдельная точка входа,
посетитель сайта её код не грузит.

Ключевое решение: **бэкендом работает сам репозиторий.** Панель читает
и (со второй фазы) коммитит `data/live.json` через API GitHub прямо из браузера
редактора. Ни сервера, ни базы, ни хостинга — поэтому платить нечему, а вопрос
«кто через год будет платить за сервер», из-за которого свою админку однажды
отложили, снимается целиком.

Побочные выгоды достаются бесплатно: история правок и откат — это git, а журнал
«кто и когда внёс неделю» ведётся сам, потому что коммит уходит от имени того,
чьим токеном опубликовали.

**Сейчас работает фаза 1 — только просмотр.** Пять экранов: обзор с проверкой
данных, неделя, альянсы, хронология, тексты. Кнопок, меняющих данные, в панели
физически нет, и за этим следит тест. Смысл такой фазы один: убедиться, что
`api.github.com` доступен из сети редактора, — если нет, вся затея не работает,
и узнать это надо до того, как написан экран ввода.

Вход, права, разбор ошибок и план дальнейших фаз — в
[`docs/ADMIN.md`](./docs/ADMIN.md).

**Одна опасность, о которой нельзя забыть:** `data/live.json` сейчас каждые
полчаса перезаписывает выгрузка из таблицы. Пока панель только читает, это
безопасно, но вместе с публикацией расписание придётся выключить — иначе
таблица будет затирать работу панели.

## Публикация

Сайт — статика: заливается как есть, собирать нечего.

### GitHub Pages

1. **Settings → General → Change repository visibility → Public**
2. **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**
3. Через минуту сайт открывается: **https://qvaden.github.io/zroute-s33/**

**Одно место с зашитым адресом:** `og:image` и `og:url` в `index.html`.
Собственно og:image обязан быть абсолютным — относительный путь браузер
поймёт, а сборщики превью в мессенджерах нет, и ссылка в чате уйдёт
без картинки. При переезде на другой хостинг поправить эти две строки;
всё остальное относительное и переедет само.

Секретов в репозитории нет. `docId` таблицы лежит в `config.js`, но он публичен
по своей природе — таблица открыта на чтение по ссылке, иначе выгрузка бы
не работала. Публичность репозитория ничего дополнительно не раскрывает.

Публичный репозиторий даёт ещё и **неограниченные минуты GitHub Actions**,
то есть выгрузка данных по расписанию ничего не стоит.

### Почему не Cloudflare Pages

Рассматривался и был отвергнут: **домен `*.pages.dev` заблокирован в России
целиком** с 9 мая 2024 — досудебная блокировка РКН всего домена из-за чужого
контента на нём. Подтверждено реестром РКН и замерами RIPE Atlas.

Netlify и Vercel тоже частично недоступны в РФ. Идеального бесплатного
зарубежного варианта для российской аудитории нет — GitHub Pages выбран
как наименее проблемный, но и он периодически деградирует.

Купить свой домен эту проблему **не решает**: блокировка идёт по IP и SNI,
а не по имени домена.

Если однажды понадобится полная надёжность для РФ — российский хостинг
(Яндекс Object Storage, Timeweb, Beget). Благодаря выгрузке данных в файл
сайт стал самодостаточной статикой, поэтому переезд занимает минуты.

### Что важно при любом варианте

Файл **`.nojekyll` удалять нельзя.** GitHub Pages прогоняет сайт через Jekyll,
а тот игнорирует всё, что начинается с подчёркивания — включая
`src/data/adapters/_coerce.js`. Без этого файла адаптеры не загрузятся,
и сайт откроется пустым без единой ошибки на странице. Тест
`I. Готовность к публикации` следит за этим.

Все пути в проекте относительные, поэтому сайт работает и в корне домена,
и в подпапке вида `/zroute-s33/`.

## Установка на телефон

- **Android / Chrome** — меню браузера → «Установить приложение». Появится
  иконка с оранжевой плашкой «33», сайт откроется без адресной строки.
- **iPhone / Safari** — «Поделиться» → «На экран Домой».

Есть быстрые ярлыки: долгое нажатие на иконку открывает переходы сразу
в «Рейтинг» и «Хронологию».

`sw.js` намеренно работает по принципу **сеть всегда первая**: пока есть
интернет, данные свежие, а кэш срабатывает только когда сети нет. Классическая
беда service worker'ов — залипшая старая версия, которую пользователь не может
сбросить. Для проекта, который ведут не программисты, такая поломка
неотлаживаема, поэтому скорость повторных загрузок сознательно принесена
в жертву предсказуемости.

### Иконки: почему SVG, а не PNG

Иконки лежат как **SVG с вложенным внутрь точным PNG** (`data:` URI). Выглядит
странно, но причина простая: репозиторий заливается через интеграцию, которая
умеет передавать только текст и портит бинарные файлы. Проверено опытом —
base64 сохраняется как текст, а сырые байты раздуваются при перекодировке
в UTF-8. SVG это текст, поэтому проходит без потерь, а картинка внутри остаётся
пиксель в пиксель.

Тест `I. Готовность к публикации` следит, чтобы в манифест не вписали `.png`:
иначе Android молча не найдёт иконку и перестанет предлагать установку.

### Два файла нужно загрузить вручную

Растровые версии обойти нельзя в двух местах:

| Файл | Зачем | Без него |
|---|---|---|
| `public/icons/icon-180.png` | иконка на iOS — Safari не принимает SVG | iOS возьмёт скриншот страницы |
| `public/og.png` | превью ссылки в чатах | ссылка будет голым текстом |

Оба уже нарисованы. Загрузить: на странице репозитория **Add file → Upload
files**, перетащить в `public/` и `public/icons/`. Веб-интерфейс GitHub
с бинарными файлами работает нормально — ограничение только у интеграции.

Перерисовать все иконки заново: `python3 scripts/make-icons.py`,
затем `node scripts/wrap-icons.mjs` для SVG-обёрток. Для работы сайта
ни Python, ни Node не нужны.

## Состояние до первого результата

История сервера на сайте начинается с недели 31 (27 июля 2026). Пока результатов
нет, сайт не показывает пустые клетки, а объясняет, что отсчёт только начинается,
и выводит состав на старте. Три места, где это учтено:

- **Главная** — экран «отсчёт начинается» вместо итогов недели.
- **Малым алам** — сравнение верхней и нижней трети не рисуется, пока нет
  результатов хотя бы за одну полную неделю: иначе оно выродилось бы
  в «0% против 0%» и подорвало бы сам аргумент.
- **Хронология** — сообщает, что летопись ещё не начата.

Недели в таблице заведены заранее, до W36. `weeksUpToLastData` отбрасывает хвост
будущих недель, поэтому «итогами недели» не может стать неделя, которая ещё
не наступила.

## Подключение Google Таблицы

Таблица уже создана, её ID прописан в `config.js`. Осталось наполнить данными
и переключить источник:

1. Заполнить `tag` и `name` во вкладке `alliances`.
2. Поставить П или Х хотя бы за одну неделю во вкладке `results`.
3. `node scripts/check-sheet.mjs` — дождаться «Готово к переключению».
4. В `config.js` поставить `dataSource: 'sheets'`.

`check-sheet.mjs` различает две разные вещи: **структура в порядке** и **готово
к переключению**. Пустая таблица формально безупречна — ни одной ошибки, все
колонки на месте, — но сайт на ней покажет нули. Поэтому проверка отдельно
сообщает, есть ли чем наполнять страницы, и возвращает ненулевой код выхода,
пока переключаться рано.

Если создаёте таблицу заново — `node scripts/make-sheet-template.mjs` отдаёт
CSV пяти вкладок, и не забудьте **Доступ → Все, у кого есть ссылка → Читатель**:
сайт читает документ по публичной ссылке, без ключей и паролей.

Инструкция для того, кто будет вносить данные дальше —
[`docs/EDITOR-GUIDE.md`](./docs/EDITOR-GUIDE.md).

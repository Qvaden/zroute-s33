# Админ-панель

Адрес: **`admin.html`** рядом с сайтом — https://qvaden.github.io/zroute-s33/admin.html

Панель открывается только с токеном GitHub. Без него это просто экран входа,
поэтому ссылку можно никак не прятать.

---

## Почему у панели нет сервера

Обычная админка — это сервер с базой. Сервер стоит денег и требует хозяина,
который через год будет платить и следить, чтобы он работал. В
[`ARCHITECTURE.md`](./ARCHITECTURE.md) именно из-за этого вопроса свою админку
однажды отложили: сервер без хозяина — отложенная смерть проекта, а вся
ценность сайта в накопленной истории.

Здесь бэкендом работает **сам репозиторий**. Панель читает и (со второй фазы)
коммитит `data/live.json` через API GitHub прямо из браузера редактора.

Что из этого следует:

- Платить нечему. Отключиться за неоплату нечему.
- История правок и откат — это git, который уже есть.
- Журнал «кто и когда внёс неделю» ведётся сам: коммит уходит от имени того,
  чьим токеном опубликовали.
- Сайт не меняется ни на строку: он по-прежнему читает тот же файл.

---

## Что панель умеет сейчас

**Фаза 1 — только просмотр.** Кнопок, которые меняют данные, в ней физически
нет, и за этим следит тест.

| Экран | Что показывает |
|---|---|
| Обзор | Проверка данных, кто правил последним, размер файла, права токена, неделя в игре |
| Неделя | Результаты всех альянсов за выбранную неделю, счётчик заполненности |
| Альянсы | Тег, название, цвет, побед за всё время, id, статус |
| Хронология | События: тип, дата, номер сервера, длительность |
| Тексты | Все тексты сайта с предпросмотром |

Смысл фазы, в которой ничего нельзя изменить, один: проверить, что
`api.github.com` вообще доступен из сети редактора. Если нет — вся затея
с бесплатной панелью не работает, и лучше узнать это до того, как написан
экран ввода.

Дальше по плану: ввод недели с публикацией одним коммитом, итог недели
(захватили/защитили), события со скриншотами, альянсы и тексты.

## Как получить токен

### Владельцу репозитория

1. GitHub → аватар → **Settings**
2. Внизу слева **Developer settings** → **Personal access tokens** → **Fine-grained tokens**
3. **Generate new token**
4. Repository access → **Only select repositories** → `Qvaden/zroute-s33`
5. Permissions → Repository permissions → **Contents: Read and write**
6. Expiration — год, это максимум, который разрешает GitHub
7. **Generate token**, скопировать и вставить в панель

Токен показывается один раз. Потерялся — выпускается новый, старый отзывается.

### Приглашённому редактору

Здесь у GitHub ловушка: **fine-grained токен нельзя выдать на чужой
репозиторий.** Он видит только то, что принадлежит своему владельцу. Поэтому:

1. Владелец добавляет человека: репозиторий → **Settings → Collaborators**
2. Редактор: Settings → Developer settings → **Tokens (classic)**
3. **Generate new token (classic)**, право — только `public_repo`

Классический токен шире, чем хотелось бы: он действует на все публичные
репозитории своего владельца. Для двух-трёх доверенных людей это приемлемо,
но если однажды перестанет быть — репозиторий переносится в **бесплатную
организацию**, и тогда fine-grained заработает и для приглашённых.

## Про безопасность честно

- Токен лежит в localStorage браузера редактора и уходит только на
  `api.github.com`. В коде и в репозитории его нет.
- В панели нет ни одного `console.log` — за этим следит тест. Случайный вывод
  токена в консоль равен его публикации.
- Репозиторий публичный, секретов в нём нет. Права токена — содержимое одного
  репозитория.
- **Худший сценарий утечки — испорченные данные.** Они откатываются через
  историю коммитов, ничего не теряется навсегда.
- Кнопка «Выйти» стирает токен из браузера. Если пропало устройство — токен
  отзывается на GitHub, и он мгновенно перестаёт работать везде.

## Две вещи, которые нельзя забыть

### 1. Панель и выгрузка из таблицы не могут писать одновременно

Сейчас `data/live.json` каждые полчаса перезаписывает
[workflow выгрузки](../.github/workflows/pull-data.yml) из Google Таблицы.

Пока панель только читает, это безопасно. **Но в тот день, когда появится
публикация, расписание придётся выключить** — иначе таблица будет затирать
работу панели каждые тридцать минут. Перевод воркфлоу на ручной запуск —
обязательный пункт фазы 4, а не пожелание.

### 2. Панель не должна кэшироваться

Для сайта устаревшая копия — мелкая неприятность. Для панели это путь к потере
данных: редактор увидит прошлую неделю и опубликует правку поверх чужой, не
заметив. Поэтому `admin.html` не подключает service worker, а сам `sw.js`
обходит и панель, и запросы к API.

## Показать панель, не выдавая доступ

```bash
node scripts/build-admin-preview.mjs
```

Собирает `dist/admin-preview.html` — один файл с настоящей вёрсткой панели
и выдуманными данными. Открывается двойным кликом, токена не просит.

## Если что-то не работает

| Что видно | В чём дело |
|---|---|
| «Токен не принят» | Скопирован не полностью, отозван или истёк срок |
| «Не найдено: Qvaden/zroute-s33» | У токена нет доступа именно к этому репозиторию. GitHub отвечает так же, если репозитория нет вовсе |
| «Не удалось связаться с api.github.com» | Сеть. У части российских провайдеров GitHub открывается через VPN |
| «У токена нет права на запись» | В fine-grained токене не выставлено **Contents: Read and write** |
| Панель показывает проблемы в данных | Тот же валидатор, что у сайта. Пока список не пуст, публиковать нельзя — смотрите, что именно он пишет |

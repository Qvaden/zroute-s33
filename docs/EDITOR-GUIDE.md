# Инструкция для того, кто вносит данные

Программировать не нужно. Всё, что требуется — Google Таблица и пять минут в неделю.

---

## Раз в неделю: внести результаты VS

1. Открыть таблицу, вкладка **`results`**.
2. Найти столбец с номером текущей недели (например `W31`).
3. В каждой строке поставить **П** (победа) или **Х** (поражение).
4. Всё. Сайт подхватит изменения сам.

Ставить можно из выпадающего списка — ошибиться нельзя. Работает с телефона.

**Заполнение одной недели — примерно минута.**

> Ячейку можно оставить пустой, если результат пока неизвестен. Пустая ячейка
> означает «ещё не внесли», а не «пропустил» — на очки она не влияет никак
> и в статистику не попадает.

---

## Раз в неделю: добавить новую неделю

Когда столбцы в `results` закончились:

1. Вкладка **`weeks`** → добавить строку:

   | id | number | startDate | endDate |
   |---|---|---|---|
   | `W37` | `37` | `07.09.2026` | `13.09.2026` |

   Колонки `serverOutcome` и `serverNumber` в той же строке — это итог недели
   на уровне сервера, см. ниже.

2. Вкладка **`results`** → добавить столбец, в заголовок написать тот же `W37`.

Порядок важен: сайт берёт список недель из `weeks` и по нему ищет столбцы
в `results`. Столбец, которого нет в `weeks`, просто не заметят.

## Вкладки таблицы

### `alliances` — кто участвует

| Колонка | Что писать |
|---|---|
| `id` | **Не трогать.** Выдан один раз и навсегда |
| `tag` | Тег в игре, например `STG` |
| `name` | Название, например `Сталкеры` |
| `color` | Цвет на графиках. Уже заполнен, можно менять |
| `active` | `да` / `нет`. Поставьте `нет`, если альянс распался |
| `note` | Любая заметка для себя |

**Про `id` — самое важное правило во всей таблице.**

Столбец `id` менять нельзя никогда. Если альянс переименуется — меняете
`tag` и `name`, а `id` оставляете. Тогда вся его история побед останется
привязанной к нему. Если поменять `id`, история порвётся и восстановить
её будет нечем.

Строки с пустыми `tag` и `name` сайт игнорирует — это заготовки под будущие
альянсы. Заполнили название — альянс появился на сайте.

### `weeks` — недели и итог сервера

Кроме дат у недели есть свой итог — не по альянсам, а по всему серверу:
ходили в атаку или отбивались, и чем кончилось.

| Колонка | Что писать |
|---|---|
| `serverOutcome` | Одно из четырёх: `взяли` · `не взяли` · `удержали` · `потеряли` |
| `serverNumber` | Номер сервера. Для захвата — чужой; при защите своего можно не писать |

Слова понимаются и по-другому: `захватили`, `защитили`, `отбили`, `не удержали`
и похожие. Регистр и лишние пробелы не важны.

**Пустая ячейка — это нормально.** Значит на этой неделе сервер не воевал или
итог ещё не внесли. Такой недели просто не будет в летописи на «Хронологии».

Итог сразу попадает на вкладку **«Хронология»**: крупной строкой про последнюю
неделю и лентой прошлых.

### `results` — результаты по неделям

Строки — альянсы, столбцы — недели. Только **П** или **Х**.

Колонки `tag` и `name` тут нужны только чтобы вы глазами видели, чью строку
правите. Сайт их не читает, можете заполнить для удобства.

### `events` — хронология

| Колонка | Что писать |
|---|---|
| `id` | Любой уникальный, например `e13` |
| `date` | `19.07.2026` |
| `type` | `server_capture` — захват сервера<br>`war` — война<br>`merge` — слияние альянсов<br>`other` — прочее |
| `serverNumber` | Номер сервера. Только для захватов |
| `title` | Заголовок |
| `body` | Описание. Можно оставить пустым |
| `imageUrl` | Ссылка на картинку. Можно оставить пустым |
| `durationDays` | Сколько дней длилось. **Необязательно** |

Захваты с номером сервера попадают на «стену трофеев» на главной странице
хронологии. Если заполнить `durationDays`, сайт сам посчитает самый быстрый
и самый долгий захват.

### `texts` — тексты разделов

Тут лежат все тексты сайта: гайд для малых альянсов, ритм недели и прочее.
Правьте прямо в ячейках, вёрстки не требуется.

Форматирование простое:

| Пишете | Получается |
|---|---|
| `## Заголовок` | Новая карточка с этим заголовком |
| `- пункт` | Пункт списка |
| `**жирный**` | **жирный** |
| `\n` | Перевод строки |

Перевод строки удобнее писать двумя символами `\n`, чем настоящим переносом
через Alt+Enter: такая ячейка не рвётся при копировании.

---

## Чего делать не надо

- **Не переименовывать вкладки.** Сайт ищет их по именам:
  `alliances`, `weeks`, `results`, `events`, `texts`.
- **Не переименовывать колонки** в первой строке.
- **Не менять `id`** ни у альянсов, ни у недель.
- **Не удалять строки альянсов.** Если альянс распался — поставьте `active` = `нет`.
  История останется, а из активного рейтинга он уйдёт.
- **Не вставлять пустые строки** посреди таблицы.

Всё остальное сломать трудно. А если что-то пошло не так — в Google Таблицах
есть история изменений: *Файл → История версий*. Любую правку можно откатить.

---

## Когда сайт обновится

**До получаса.** Сайт не читает таблицу напрямую — раз в полчаса её забирает
служебный скрипт и складывает данные рядом с сайтом. Сделано это ради
надёжности: Google в России работает нестабильно, и при прямом чтении часть
игроков видела бы пустую страницу.

Если ждать не хочется, обновление можно запустить вручную: на странице
репозитория вкладка **Actions → «Выгрузка данных из таблицы» → Run workflow**.
Займёт около минуты.

---

## Если что-то выглядит сломанным

Попросите разработчика запустить проверку:

```bash
node scripts/check-sheet.mjs <ID документа>
```

Она читает таблицу так же, как сайт, и печатает понятный список замечаний:
какая строка, какая колонка, что не так.

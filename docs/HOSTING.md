# Где живёт сайт: хостинг, домен и сертификат

Документ нужен, чтобы вопрос «а почему не GitHub Pages?» не всплывал заново.
Он же — инструкция по восстановлению после аварии.

## Коротко

```
GitHub (исходники, история, правки) ──push──> Netlify (раздача файлов + TLS)
                                          └─> GitHub Pages (зеркало, спит)
Supabase — данные форума, админки, рейтингов (это не файлы)
NicNames — только регистрация домена; DNS-зона перенесена в Netlify
```

Публиковать надо **одну** ссылку: `https://zroutehub.bond`.

## Почему не GitHub Pages

Не из-за удобства, а из-за сертификата. Pages умеет отдавать HTTPS на
кастомный домен, но сертификат для него должен выпустить сам GitHub. С
марта 2024 он делает это только оптовыми прогонами и не гарантирует выпуск
для новых доменов, а для редких TLD вроде `.bond` выпуск практически не
происходит никогда. Практически это выглядит так: домен настроен, ждёшь
сертификат, он не появляется. Проверено на себе.

> **Важно для того, кто правит сайт:** ждать возобновления выдачи сертификатов
> GitHub бессмысленно. Если `https://zroutehub.bond` снова показывает ошибку
> сертификата — надо чинить выдачу сертификата на стороне того, кто терминирует
> TLS (сейчас это Netlify), а не возвращаться на Pages.

Диагноз всегда один и тот же: сам сайт из России доступен, блокировки нет —
ломается только TLS-рукопожатие. Проверить можно так (см. «Как диагностировать»).
